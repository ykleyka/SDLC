# Хранение данных в SQLite через EF Core

## Контекст и постановка задачи

Приложение хранит группы, участников, траты и историю. Его запускают на ПК разработчика и на компьютере преподавателя, поэтому установка должна быть максимально простой (REQ-INST-001). Нагрузка небольшая: до 20 одновременных пользователей (A-3).

Какую СУБД использовать, чтобы не требовать установки сервера БД и при этом обеспечить транзакции и миграции?

## Драйверы решения

* Запуск одной командой `dotnet run` без установки СУБД (REQ-INST-001, 002)
* Бесплатность и свободная лицензия (C-4, REQ-COST-001)
* Транзакции для сохранения траты с долями (REQ-REL-001)
* Работа на Windows, Linux и macOS (REQ-PORT-001)
* Достаточная производительность для 20 пользователей (REQ-PERF-001)

## Рассмотренные варианты

* SQLite
* PostgreSQL
* SQL Server LocalDB

## Итог решения

Выбранный вариант: «SQLite», потому что это единственный вариант, работающий без установки и настройки на всех трёх ОС, а его ограничение на параллельную запись не важно при 20 пользователях.

### Последствия

* Хорошо, потому что база — один файл `evenup.db`, создаётся миграциями при первом запуске
* Хорошо, потому что для тестов можно использовать SQLite in-memory с той же схемой
* Плохо, потому что SQLite не имеет типа `decimal`; суммы хранятся как `TEXT` через конвертер (SDD SYS-NFR-005)
* Плохо, потому что записи сериализуются; включается режим WAL, чтобы чтение не ждало записи
* Нейтрально, потому что при переходе на PostgreSQL достаточно сменить провайдер EF Core и пересоздать миграции

### Подтверждение

Проверяется запуском на чистой машине: после `dotnet run` создаётся файл БД и открывается страница входа. Тест сервисов проверяет, что сумма 0,10 + 0,20 сохраняется и читается как ровно 0,30.

## Плюсы и минусы вариантов

### SQLite

* Хорошо, потому что не требует установки
* Хорошо, потому что кроссплатформенный
* Плохо, потому что одна запись в момент времени
* Плохо, потому что нет нативного `decimal`

### PostgreSQL

* Хорошо, потому что полноценная серверная СУБД с `numeric`
* Плохо, потому что требует установки или Docker на каждой машине
* Плохо, потому что избыточна для учебной нагрузки

### SQL Server LocalDB

* Хорошо, потому что хорошо интегрирован с Visual Studio
* Плохо, потому что работает только на Windows (нарушает REQ-PORT-001)

## Дополнительная информация

Связано с ограничением C-2 и допущением A-3 SRS. Пересмотреть при росте числа одновременных пользователей выше ~100 или при развёртывании нескольких экземпляров сервера.
